## 1. 목표

응급실에서 환자 내원부터 퇴실·전원까지 중증도 평가, 자원 배정, 진료·투여, 모니터링, 타 서비스 연계를 **단일 Bounded Context(EMG)** 로 제공한다.

## 3. 기능 요구사항 요약

### FR-TRIAGE
- 119 사전정보 조회·저장
- KTAS 초기/재평가 이력 관리
- 활력징후·EWS 기록
- 격리 유형 등록·해제 (DUR은 조회만)
- 패혈증/뇌졸중 스크리닝 결과 저장

### FR-RESOURCE
- 구역·병상 마스터 및 배정/해제
- 구역별 혼잡도 지표 산출(종합 현황판에서 사용). 의료기기 할당·NEDIS 연계는 제외

### FR-CARE
- 접수 유입 응급환자 목록 제공(RCP Consumer)
- 진료기록·처치·MAR·CPR 타임라인 기록, 동의 기록(종이 동의서 수령 사실)
- MAR/처치는 GR2 `orderId` 참조 (처방 이중기입 금지)

### FR-ORDER-CHANNEL
- 응급 UI에서 GR2 처방코어만 호출해 처방 생명주기 처리
- LAB/PHM/SUR **직통 오더 생성 금지**
- 협진·당직·수술 긴급 요청은 범위에서 제외

### FR-MONITOR / FR-DISPOSITION
- 현황판(재실·병상·혼잡도)·LOS 알림 생성 배치와 확인 처리
- 퇴실 유형(귀가/입원/전원/사망/DAMA) 결정
- 입원요청·전원소견서 (구급차 이송 기록은 제외)
- 입원요청은 Kafka 이벤트로 병동(IPT)에 직접 전달(`ADMISSION_REQUESTED` → 병동이 `BED_ASSIGNED`/`ADMISSION_REJECTED` 회신), 원무 경유·오케스트레이터 없음. 병상 가용 조회(GET)는 IPT에 동기로 유지. 상세: `flow.md` 7-1장

### FR-CODE
- (제외) EMG 전용 코드 CRUD는 삭제. 코드는 admin 공통코드 캐시를 우선 사용하고 없으면 코드 안 폴백 상수 사용

## 7. 보류한 개선 과제 (합의·요청 후 진행)

### 7.1 오접수·중복 접수 정리 (2026-10-06 논의, 보류)

**문제** — 접수가 같은 환자를 중복으로 접수했는데(중복 경고 `GET /care/patients/active`를 무시) 그중 한 건이 잘못 들어온 경우, 응급에서는 접수를 지울 수 없다(삭제는 상태 변경 규칙, 삭제 기능 없음). 정상 절차는 접수가 잘못 들어온 한 건을 취소하는 것이고(응급은 취소 이벤트로 `Cancelled`), 응급 직원이 그 접수에 KTAS·활력징후·병상·처치 같은 기록을 이미 입력했다면 접수의 취소 가능 여부 조회가 `HAS_RECORDS`라 접수에서 취소할 수 없다. 지금은 기록이 있는 접수를 정리할 방법이 없다(퇴실 처리로 닫는 것이 가장 가깝지만 사유 구분이 안 된다).

**임시 운영 원칙** — 중복 접수를 알게 되면 응급 기록을 입력하기 **전에** 접수에 어느 쪽을 취소할지 알리고, 진료는 남길 접수 한 건에만 입력한다.

**하려면 필요한 것**

| 구분 | 내용 | 담당 |
| --- | --- | --- |
| 퇴실 유형 | `ER_DISPOSITION_TYPE_CD`에 `06` 오접수·중복 접수 추가 (사용 `Y`, 정렬 맨 뒤). 응급 폴백 목록(`EmgCodes`, 프론트 `DISPOSITION_TYPE_FALLBACK_OPTIONS`)에도 추가. 공통코드는 admin 소유라 응급이 직접 못 넣는다 — admin이 추가하기 전에는 화면에 안 보이고 서버도 받지 않는다 | **admin 요청** |
| 사유 | 퇴실 결정에 사유(자유 입력)를 남기는 칸. 지금 `DISPOSITION`에는 사유 컬럼이 없어 컬럼 추가(DDL)와 요청·응답·화면 입력칸이 필요하다. 사유를 코드로 나누려면 사유 코드 그룹을 admin에 따로 요청 | 응급 + DDL(직접 실행) |
| 접수와의 어긋남 | 응급이 "오접수"로 닫아도 접수 서비스에서는 그 접수가 계속 진행 중으로 남고, 응급 기록이 있어 접수가 취소도 못 한다. 응급이 닫은 사실을 접수에 알려(이벤트) 접수가 강제 취소 처리하는 방법을 합의해야 한다 | **접수팀과 합의** |
| 수납 | 그 접수에 수납이 생겼다면 수납 쪽 정정이 따로 필요 | 수납팀 확인 |
| 통계 | 오접수 건은 환자 수·체류 시간 통계에서 제외 (현황판 재실 수는 퇴실로 이미 빠진다) | 응급 |
| 권한 | 기록이 있는 접수를 닫는 일이라 의사만 선택하게 할지, 사유를 필수로 할지 결정 | 응급 + 업무 확인 |
| 중복 표시 | 환자 목록 응답(`EmergencyPatientDto`)에 `patientId`를 추가하고, 같은 환자의 진행 중(In Care) 접수가 둘 이상이면 목록에서 눈에 띄게 표시. admin 요청 불필요 | 응급 |

**진행 순서(안)** — ① admin에 `06` 추가 요청 → ② 접수팀과 "오접수로 닫은 뒤 접수 처리" 합의 → ③ 합의 뒤 응급 구현(퇴실 유형 `06`, 사유 컬럼·입력칸, `patientId`와 중복 표시).

**요청할 공통코드**: 그룹 `ER_DISPOSITION_TYPE_CD`, 코드값 `06`, 이름 "Erroneous / duplicate registration"(오접수·중복 접수), 사용 `Y`, 정렬 순서 마지막.
